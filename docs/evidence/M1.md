## What M1 implements
One skill, natural language or `/pbd`; the agent orchestrates `pbd start → submit reading (one reader per declared source) → submit claims → submit design → submit review (separate reviewer) → finalize`. The runtime verifies reader quotes against cited lines (and PDF pages), accounts for every source member and reader obligation, enforces requested levels, content shape per type, no generated assignments/dates/effort, a disposition per effective claim, templated-output rejection, schema and invariants; computes G01–G18 and re-verifies every PASS against artifact hashes, run and stage. Outputs: `report.html` (two layers, offline, CSP, sanitized, search/filters), `backlog.json`, `requirements.json`, `acceptance-criteria.json`, `traceability.json`, `findings.json`, `questions.json`, `metrics.json`, `gates.json`, `checks.json`, `manifest.json`, optional Markdown, CSV, XLSX, Mermaid and a local Azure package (native fields, HTML formats, JSON Patch, proposed values never written). Profiles: generic, Azure Agile, Scrum, Basic, CMMI, custom JSON. Sources: UTF-8/UTF-16/cp1252 text, DOCX (body, tables, headers, footers, notes, comments), XLSX (all sheets, cells, formulas), PDF with text layer (optional `pypdf`), images as visual members.

### Interpretation of gate outcomes
G02 FAIL mostly reflects obligations the independent reviewer judged partially covered because the *source* is ambiguous and a question was raised; G02 stays strict by design (a partial obligation is a gap) and the report shows the breakdown. G01 is BLOCKED exactly where reading was incomplete (c10 diagram, c11 PDF page 3); nothing was invented for those parts. G17 is BLOCKED whenever an Azure package uses unverified default profiles. G07 NOT_RUN in c04/c08 means the reviewer did not give a valid task-sufficiency verdict (c08 used an invalid value later rejected by the fixed validator).

## Defects found by the dogfood and fixed (each with a regression test)
1. Claims stage stored uncertainty shapes the design stage rejected → runs stuck (c05, c08, c10); fixed at submission, invalid runs replaced (ledgers replayed unchanged, disclosed).
2. Profiles missing from the wheel (non-editable install could not load any profile).
3. Phantom extra line for files ending in newline (readers could never prove full coverage).
4. List-style criteria dropped their expected outcomes when a statement was present.
5. Duplicated story prefixes ("Quando Quando") and ungrammatical joins; designer procedure clarified.
6. Criterion references to non-existent visible IDs; designer procedure requires keys.
7. Reviewer contract lacked allowed values; `task_sufficiency` was not validated.
8. Reader contract lacked allowed uncertainty values.
9. Report widened by 173 px on phones (long digests).
10. Reviewer could be one of the readers while claiming independence.
11. Mypy failures slipped through the first commit gate script (`&&` under `set -e`); gate rewritten.

## Observations and limitations
- Blindness is enforced by sandbox scoping and instructions, not OS access control; agent identities are self-reported.
- The permission classifier blocked *resumed* agents from switching to the frozen runtime; c01–c04, c07, c08, c10 designs were submitted with the editable runtime (working tree at `cbdc137` plus uncommitted extraction changes not on the design path). Runtime per stage is recorded in `runs-summary.json`.
- Visual reading of PDF pages is not available on this host (`pdftoppm` missing for the agent's file reader); c11 page 3 correctly stayed unread. Image vision and `visual_transcription` are implemented and unit-tested but not exercised in a dogfood.
- One reviewer read only the first ~6 KB of rendered descriptions (disclosed in its report). One reviewer wrote its JSON through a Python file containing only hand-written judgments (no automated extraction).
- `pbd skill install` works from a checkout, not from a wheel (skill assets are not packaged).
- The new-session Claude Code dogfood (skill coordinating everything from one request) was deferred at the owner's request to limit multi-agent cost. Skill discovery by a fresh session was verified earlier.

## M1 exit assessment
Met: agent-led generation from a single PRD and from multiple sources with separate readers, generator and reviewer; selective levels; native formatting and criteria styles; deterministic JSON/HTML and optional exports; local Azure package schema; structural, browser, security and cross-format tests; independent review on every case. **Not yet met**: an end-to-end new-session run driven only by natural language, and Linux symlink qualification. M1 is therefore reported as **substantially complete with two open items**, not as fully complete.
