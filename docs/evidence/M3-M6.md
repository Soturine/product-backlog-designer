## What is implemented
- **M3** (`integrations/azure`): snapshots keep absent/unavailable/unknown distinct and report truncation; a dynamic profile comes from snapshot metadata. `prepare` emits schema-valid plans (CREATE/UPDATE bound to revisions/UNCHANGED/CONFLICT/DEFERRED; identity by `pbd-id` tag; no DELETE; forbidden fields never written; human edits since the last publication are conflicts). `approve` binds digest, target, approver and time. `apply` goes through the default-deny authority, only on the mock, with a write-ahead journal: idempotent resume, reconciliation of lost responses, bounded retries for 429/5xx/timeouts, stop on 401/403, 412 fails without overwriting, failed parent links are PARTIAL, nothing deleted. `verify` reads back in batches and can at most be MOCK_VERIFIED. Tested failure modes: 401, 403-equivalent stop, 404, 412, 429 with retry-after, 500/503, timeout, lost response, incomplete read-back, parent-link failure, ambiguous identity, type change; Unicode/HTML round trip; the whole flow inside the zero-network guard.
- **M4** (`pipeline/planning.py`, `pbd plan`): only confirmed values (proposed on request, labelled); zero ≠ absent; no unit conversion; no capacity → sequence only; no calendar → no dates; MoSCoW/RICE/WSJF only with complete inputs; cycles, invalid relations, external blockers, cross-team dependencies, oversized items; scenarios uncommitted; staleness by backlog digest.
- **M5** (`pipeline/evolution.py`, refine extensions, `pbd evolve`): formatting-only vs content source diffs; approved decisions supersede claims (recorded on both sides); retrace, supersede, split and merge with lineage; titles change in place, re-creation refused; human edits need explicit keys; no-ops classified unchanged; replays on a newer version are conflicts; stale plans/packages/approvals listed.
- **M6** (`pipeline/handoff.py`, `pbd handoff ftd`): original sources with FTD roles and digests, requirements with locators and quotes, decisions, open questions, work items with criteria, verified tracker links only, a draft FTD request (criteria as seeds, questions as ambiguities), no test cases. Integrated flow test runs generate → audit → compare → refine → plan → evolve → stale detection → re-plan → package → mock publication → FTD handoff inside the zero-network guard.
