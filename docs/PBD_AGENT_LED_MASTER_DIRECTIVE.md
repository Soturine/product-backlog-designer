# PBD — Agent-led implementation master directive

Use this directive in a clean development workspace for this repository. You are the implementation agent, not a report-only reviewer. ## Non-negotiable scope
Build ONE agent-led, local-first, portable skill. Primary intent: generation from zero, with any sufficiently informative selected source set; existing backlog optional for audit, comparison, refinement and incremental changes. Natural language or /pbd is the default. No mandatory command chaining, LLM API service, Docker, cloud database, preexisting backlog, target credentials or configuration wizard. Do not hardcode a domain, source names, item counts, estimates, profiles or expected benchmark output. Support selective levels and clear questions when input insufficient.

The agent interprets actual sources and performs semantic work; runtime performs deterministic contracts, IDs, provenance, graph, validation, state, rendering, local packaging and mockable transport. One logical reader per explicitly declared source, directory/archive counts as one; use bounded source-specific chunks, complete member ledger, page/section/path/line locators, no generated script to bypass semantic reading. Separate source-first reviewer, record independence and fallback. Do not manufacture agent results, receipts, metrics or claimed test execution.

**Absolute execution restriction for this implementation round: NO live Azure calls, reads or writes; no login, PAT, network transport, validateOnly against real targets, or use of saved remote URLs.** Use fixtures and in-memory/localhost mocks only. Implement future transport behind explicit opt-in and exact-plan approval, default offline, test denial on absent authority, stale approval, wrong target and ambiguous response. Any future live qualification requires separately authorized disposable sandbox; leave it NOT_RUN. No production system interaction. No private sources, identifiers, corporate business logic, credentials, screenshots, logs or benchmark metrics in Git, generated tests, public artifacts or prompts; all fixtures invented independently. Never copy private input into repo. Inspect diff and staged content before any commit. No AI co-author trailer. No release/tag or automatic remote CI. Preserve existing work; use small checkpoints and report exact commits. Prefer local qualification before optional remote CI. Do not choose a project license or incorporate third-party code until per-file license/notice compatibility and owner decision are confirmed; concept-level adaptation/original implementation is allowed. Record upstream pin and adoption tests. Use FTD generic primitives, Assertiva report patterns, Derivanta governance and QE Engineering strategy only where verified compatible; no bulk framework imports.

## Implementation checkpoints
CP0 / M0: inspect actual repository and upstream candidates; baseline clean state, document dependency/license decisions, threat model, package/skill layout, install and host detection. Define strict versioned canonical schemas (sources, claims, items, criteria, relations, questions, decisions, findings, fields/provenance, gates, run manifest, plans/receipts). Stable identity independent of title/position; preserve native tracker ID namespace. Explicit uncertainty, effective versions, supersession and typed evidence. Add allowlist/path/symlink/archive safety, atomic state, checkpoint invalidation, privacy tests, CLI help and zero-network default. Exit: local unit/property/contract tests, schema fixtures valid/invalid, docs and actual test evidence.
CP1 / M1: build agent procedures and orchestration contract, not a Python keyword generator. Requirement ledger and domain model, Epic/Feature/Story/AC/Task decomposition, technical proposals, traceability, dependency graph. Format Stories with native bold prefixes, acceptance as list/table/Gherkin (stable criterion IDs and expected outcomes); support enabler/spike and no fake actor. One-command generation with PRD only, multiple-source paths, selective generation. Deterministic HTML/JSON outputs and optional MD/CSV/XLSX; offline report with executive and technical layers, full searchable tree, every item/criterion, source evidence, differences, questions and status. Implement local Azure package schema. Exit: actual host-led synthetic run plus independent review, structural and browser/security/cross-format tests. No claims beyond evidence.
CP2 / M2: implement audit, compare, refine, profile, source-first independent coverage/reverse trace, INVEST/QUS-inspired reviewer rubric, semantic duplicate candidates, contradiction, stale scope, task sufficiency, false-positive controls. Unknown/optional fields are not defects by default; no arbitrary quotas. Compare many-to-many across alternatives. Produce expected/actual/why/impact/recommendation and per-item/criterion dispositions, source locators, denominator provenance. Exit: independently adjudicated positive/negative/mutation fixtures; test evaluators, report unresolved gaps.
CP3 / M3: local Azure snapshot ingestion/discovery contracts; mock REST WIQL and batch reads, 200 limit, UTF-8, pagination, IDs, partial metadata and revisions; process types, field mappings, native HTML, hierarchy/relations, board/sprint settings, custom rules. Plan exact create/update/unchanged/conflict/deferred with hashes, revision checks, no auto-delete, no bypass, safe idempotent journal and ambiguous create reconciliation. CLI-friendly local package + preview; primary REST adapter behind approved future boundary, optional CSV with fidelity limits. Mock read-back and failure/recovery tests; production/live NOT_RUN, never call external Azure. Exit: contract tests and offline mock round-trip, not live qualification.
CP4 / M4: dependency-aware planning, team-owned estimates, confirmed capacity/dates/scale, separate actual and proposal, missing capacity yields sequencing only. No assignment, time logging or official estimate. Exit: graph and capacity regression, unknown/empty/zero handling.
CP5 / M5: version/ADR diffs, explicit supersession, stable split/merge lineage, semantic vs metadata revision, impact/reconciliation, stale approval invalidation and preservation of human edits. Exit: version mutations, concurrency and repeat-run/idempotency tests.
CP6 / M6: FTD handoff without replacing original sources; optional other tracker/host adapters only after primary path reliable. Run reproducible benchmark protocol with bare agent and comparable open baselines; independently reviewed gold, private calibration only if authorized and outside Git, separate holdout, same inputs/budget where feasible, disclose noncomparable features. Record actual models, artifacts, reviewer independence, counts/denominators, false positives/negatives, costs/variance and skipped live tests. No superiority claim without evidence.

## Required engineering behavior
Use existing gate IDs G01–G13 unchanged and add stable extensions G14–G18 as specified in [quality gates](quality-gates.md); do not renumber. Semantic gates require real review, deterministic gates require recorded executable checks; missing evidence BLOCKED/NOT_RUN. Reconcile source-first inventory and reverse trace, include every item and criterion, distinguish incomplete reading from no coverage. Correct root causes, not expected outputs. Never convert missing coverage into PASS by shrinking denominator. Bounded correction rounds, regression for each discovered defect. Local pytest, property tests, contract mocks, static analysis, Playwright/offline HTML, security and mutation tests as applicable; pin environment and distinguish mocks from actual agent dogfood. Run compatible Derivanta/Assertiva versions only if available and record exact commands/results; otherwise mark NOT_RUN. Maintain docs links, examples, changelog and crosswalk. Never falsely mark milestones complete; separate runtime readiness from live qualification. Avoid endless polishing: stop at checkpoint exit criteria, list remaining defects and blockers.

## Deliverable and exit report
Return actual repo diff/commits, checkpoints passed/blocked, exact commands, test counts/skips/failures, artifact paths and hashes, real agent evidence, known limitations, privacy checks and next checkpoint. Include explicit statement of zero Azure calls/writes and how tested. Do not publish a release. If scope cannot be completed, deliver coherent partial implementation and evidence, not an empty scaffold or fabricated success.
