# Evidence, authority and backlog health

## Authority and temporal consistency
Maintain source versions and effective/superseded claim edges, explicit authority roles and unresolved conflicts. When an approved decision replaces an earlier mechanism, find all affected stories, criteria, tasks and tests; preserve still-valid obligations; propose minimal revisions and new work only for uncovered obligations. A human backlog is a comparator, not a normative source unless explicitly designated. Compare snapshots as of different times without silently merging. Track item revision separately from business content: board metadata churn is not a scope change. Review changes to descriptions, criteria, hierarchy, fields, and relations separately. Code/commit references and closed states are not verified delivery evidence. Separate source obligation, static code observation, test plan, executed test and acceptance evidence.

## Health review
Inspect all work items individually and compare against source and profile. Classify confirmed conflict/gap, candidate concern, optional improvement, question, or justified exception. Do not equate missing optional fields, terse descriptions, root iteration, unassigned work, an open parent with closed children, a technical enabler without persona, an orphan cross-cutting item or duplicate title with a definite defect. Confirm semantic similarity and whether legitimate cross-cutting work is represented. Do not infer Done, customer approval, actual hours, or deployed behavior. Report exact expected/actual, source locator, impact, suggested resolution, affected IDs and review status.

## Criteria fidelity
Canonical criterion: stable ID, parent, claim references, source locators, condition/trigger, expected outcome(s), exceptions, optional verification approach, status, origin and original raw representation. For imports preserve visible IDs and map missing IDs deterministically without rewriting originals. Recognize list items, tables (header versus data rows; merged cells; nested lists), Gherkin, prose and mixed formats. Report raw presentation row count versus normalized criterion count versus atomic obligation count; never silently discard cells or infer one row equals one obligation. Render selectable native HTML list, table (ID / acceptance condition / expected result), or Gherkin. Preserve rich text semantics, UTF-8, ordering and separate native acceptance field. Sanitize render view, retain original securely. Test semantic equivalence across representations and no fabricated extra conditions. Distinguish source thresholds from suggested targets, and observable expected behavior from test procedure or assertion of execution.

## Planning evidence
Original estimate, remaining work, completed work, story points, effort, business value, time criticality, priority and risk are distinct. Zero, missing, unavailable and not applicable are separate states. A configured iteration is not proof of capacity; an empty capacity response is not proof nobody is working. Propose sequencing when capacity unknown; do not allocate dates or staff. DoR/DoD and time tracking may use external extension storage; a field or form layout cannot prove extension data was exported. Unknown custom fields are preserved read-only; never write server-managed fields. Discover allowed types, field constraints, team hierarchy, board settings and permitted values before preparing target-bound changes.

## Integration evidence
Treat local imports, metadata discovery, history and verification as separate scopes. Record query visibility, as-of, requested/received IDs, duplicate/missing/unexpected IDs, batch limit, unavailable endpoints and permissions. Metadata and revision reads need not be atomic with item snapshot. Do not interpret unsupported layout or extension endpoint as absent configuration. Revision histories are optional, paginated and explicitly scoped; validate sequences, record gaps and compare semantic fields independently of board metadata. No remote access during offline qualification.
