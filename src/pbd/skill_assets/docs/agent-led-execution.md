# Agent-led execution contract

Generation from scratch is the primary product, not an extension of backlog import. A PRD alone, or any explicitly selected authorized source set containing enough evidence, can initiate generation. No existing backlog, tracker, credentials, code, TDD, or mandatory instructions file. With inadequate evidence, generate supported scope and clearly report blocked obligations; never fabricate requirements. Audit, comparison, selective generation, planning and incremental updates are optional intents.

## Roles and boundaries
The host agent owns orchestration, source interpretation, requirements synthesis, decomposition, semantic audits and decisions. Assign one logical reader per declared source (one directory or archive is one source); enumerate its members and bounded chunks; never equate inventory with reading. Readers must actually inspect text, tables, diagrams, images and relevant code, recording page/section/path/line locators, coverage ledger and unreadable/omitted portions. When delegation is unavailable, use explicit sequential roles and disclose reduced independence. Do not use a generated script, regex, keyword counts, prewritten answers, or an LLM API wrapper to bypass semantic work. Deterministic extraction, parsing, hashing, formatting and metrics are allowed as support, never as a semantic verdict.

Orchestrator freezes source scope, authority, version, hash and role; readers produce separate claim ledgers. Reconcile equivalent obligations without erasing locators. Functional and technical authorities are distinct; approved decisions can explicitly supersede old claims. Preserve historical claims and lineage, unresolved conflicts and proposed work. A code snapshot is implementation evidence at its version, not proof of runtime behavior, deployment or approved scope. Test cases are corroboration, not automatically requirements. Never mix branches silently; archive/container names do not prove chronology or deployed version. Track configuration, middleware and infrastructure as independently evidenced dependencies.

Specialists design value slices, criteria and tasks using [methodology](methodology.md), [story engineering](story-engineering.md), [acceptance engineering](acceptance-engineering.md), [planning](planning-engineering.md). Combine roles for small runs, split by capability for large runs; no mandatory number of generators. Maintain stable IDs and trace links. Reviewers re-read original authorities before seeing generated coverage claims, then reconcile against every item and criterion. Record review scope and agent independence. Runtime validates structure and renders output, never substitutes for independent review. Stop bounded correction loops on lack of progress; report unresolved failures, not artificial green gates.

## Run state and evidence
A local manifest records selected sources/roles/versions, stage checkpoints, reader completion, artifact hashes, review provenance, exact mode, limitations, and gate results. Invalidate downstream stages when source or authority changes. Write canonical JSON first, render HTML and exports deterministically. Audit coverage uses independent denominators; a partial inventory cannot certify completeness. Separate status of run, source coverage, semantic review, publication readiness and actual remote state. Missing input, absent value, inaccessible data, unknown, inferred and proposed are distinct.

## Isolation and qualification
Default offline generation and benchmarking. No network to any corporate system, no credentials, no live tracker calls, no mutation, even if a local snapshot contains a destination URL. Mock all tracker interactions during development; explicit future authorization of a disposable target is required for live qualification. A local package is an artifact, never authorization to apply it. Public repositories contain original generic implementation and entirely synthetic examples, not private sources, content, IDs, identifiers, metrics or derived business rules. See [benchmark isolation](../benchmarks/calibration.md), [gate extensions](quality-gates.md) and [master directive](PBD_AGENT_LED_MASTER_DIRECTIVE.md).
